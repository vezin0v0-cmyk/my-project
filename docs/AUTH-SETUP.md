# Как включить настоящие аккаунты Nova

Сайт Nova уже подключён к проекту Supabase `nova`, письма уходят через Gmail. Эта инструкция нужна, если придётся настроить всё заново: новый проект, другая почта-отправитель или свой домен.

Без ключей кабинет работает в демо-режиме: код подтверждения показывается прямо на странице. С ключами код приходит **настоящим письмом от «Nova»** на почту, которую человек ввёл при регистрации.

Что для этого нужно:

- **Supabase** — бесплатный сервис. Он хранит аккаунты (пароли в зашифрованном виде) и проверяет код.
- **Почта-отправитель (SMTP)** — ящик, с которого уходят письма.
- **Два ключа** — их нужно вписать в сайт.

Займёт около 20 минут. Всё делается в браузере, программировать не нужно.

> На бесплатном тарифе Supabase не даёт заменить письмо, пока не подключена своя почта-отправитель. Поэтому сначала шаг 5, потом шаг 4.

> Названия кнопок в панели Supabase иногда меняются. Если пункт называется чуть иначе — ищи по похожим словам.

---

## Шаг 1. Создай проект в Supabase

1. Открой [supabase.com](https://supabase.com) → **Start your project** → войди через GitHub.
2. **New project**:
   - **Name:** `nova`
   - **Database Password:** нажми **Generate** и сохрани пароль у себя. Никому его не отправляй.
   - **Region:** ближайший к твоим пользователям (например, Central EU — Frankfurt).
3. **Create new project** и подожди пару минут, пока проект создаётся.

## Шаг 2. Скопируй два ключа

Нажми кнопку **Connect** вверху панели или открой **Project Settings → API Keys** (адрес проекта — в **Project Settings → Data API**).

Нужны два значения:

| Что | Как выглядит |
|---|---|
| **Project URL** | `https://abcdefgh.supabase.co` |
| **Publishable key** (в старых проектах — **anon public**) | `sb_publishable_...` или длинная строка `eyJ...` |

Эти два значения **публичные**: они всё равно будут видны в коде сайта, их можно присылать в чат.

**Никому не отправляй** `secret` / `service_role` ключ и пароль базы данных.

## Шаг 3. Включи код вместо ссылки

**Authentication → Sign In / Providers → Email**:

- **Confirm email** — включено. Без этого письмо не отправится.
- **Email OTP Length** — `6`. Сайт ждёт 6 цифр.
- **Email OTP Expiration** — `900` (15 минут). Так написано в письме.

Сохрани (**Save**).

## Шаг 4. Вставь красивое письмо Nova

**Authentication → Emails → Templates → Confirm signup**:

1. **Subject (тема):** `Код подтверждения Nova`
2. **Message body:** переключись на исходный код (**Source**), сотри всё и вставь целиком файл [`docs/email/confirm-signup.html`](email/confirm-signup.html). На GitHub открой его, нажми **Raw** и скопируй всё.
3. **Save**.

Справа появится предпросмотр: тёмное письмо с золотым кодом.

> Если пропустить этот шаг, вместо кода придёт стандартное письмо со ссылкой на английском.

Так же замени ещё два письма:

| Шаблон в Supabase | Тема | Файл |
|---|---|---|
| **Reset password** | `Код для нового пароля Nova` | [`docs/email/reset-password.html`](email/reset-password.html) |
| **Password changed** (раздел Security notifications, сначала включи его) | `Пароль Nova изменён` | [`docs/email/password-changed.html`](email/password-changed.html) |

Первое приходит после «Забыли пароль?» на сайте. Второе — после любой смены пароля: если пароль сменил не хозяин аккаунта, он сразу узнает.

## Шаг 5. Подключи почту-отправителя

Встроенная почта Supabase — только для проверки: письма доходят лишь участникам твоей команды в Supabase, и их очень мало в час. Обычным людям код не придёт. Нужен свой отправитель. Выбери один вариант.

### Вариант А — Gmail (бесплатно, 10 минут)

Письма будут приходить от **«Nova» &lt;адрес Gmail&gt;**.

1. Заведи **отдельный** Gmail для проекта, например `nova.windows.team@gmail.com`. Не используй личную почту: её адрес увидит каждый, кто регистрируется.
2. В этом аккаунте Google включи **двухэтапную аутентификацию**: myaccount.google.com → Безопасность.
3. Открой [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords), создай пароль приложения с названием `Nova` и скопируй 16 букв.
4. В Supabase: **Authentication → Emails → SMTP Settings → Enable Custom SMTP**:

| Поле | Что вписать |
|---|---|
| Sender email | твой новый Gmail |
| Sender name | `Nova` |
| Host | `smtp.gmail.com` |
| Port | `465` |
| Username | тот же Gmail |
| Password | пароль приложения из пункта 3, без пробелов |

5. **Save**.

Gmail отправляет до ~500 писем в день. Для старта этого хватит с запасом.

### Вариант Б — свой домен (самый «официальный»)

Письма будут приходить от **«Nova» &lt;noreply@твойдомен.ru&gt;**. Так делают большие сервисы, и такие письма реже попадают в спам.

1. Купи домен (например, на reg.ru — от ~200 ₽ в год). Сайт Nova потом тоже можно открыть на этом домене.
2. Зарегистрируйся в [resend.com](https://resend.com). Бесплатно — до 100 писем в день.
3. **Domains → Add domain**. Resend покажет несколько DNS-записей: добавь их в панели, где покупал домен, и дождись статуса **Verified**.
4. **API Keys → Create API key** — скопируй ключ.
5. В Supabase: **Authentication → Emails → SMTP Settings → Enable Custom SMTP**:

| Поле | Что вписать |
|---|---|
| Sender email | `noreply@твойдомен.ru` |
| Sender name | `Nova` |
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | API-ключ из пункта 4 |

Можно начать с Gmail, а когда будет домен, просто поменять эти поля. На сайте ничего переделывать не придётся.

**Лимит писем.** После подключения своей почты загляни в **Authentication → Rate Limits**: там задано, сколько писем в час может уйти. По умолчанию немного. Если регистраций станет много, увеличь.

## Шаг 6. Укажи адрес сайта

**Authentication → URL Configuration → Site URL:**
`https://vezin0v0-cmyk.github.io/my-project/`

Это адрес сайта на GitHub Pages. Он заработает, когда сайт будет опубликован (см. раздел «Сайт» в README).

## Шаг 6½. Включи удаление аккаунта и хранилище фото

**SQL Editor → New query**: вставь целиком файл [`supabase/avatars.sql`](../supabase/avatars.sql) и нажми **Run**. Затем так же — [`supabase/account.sql`](../supabase/account.sql).

- `avatars.sql` — место для фото профиля: каждый может менять только своё фото.
- `account.sql` — кнопка «Удалить аккаунт» в профиле. Удалить можно только свой аккаунт и только сразу после ввода пароля.

## Шаг 7. Впиши ключи в сайт

Самый простой путь: **пришли мне в чат Project URL и Publishable key**, и я вставлю их сам.

Или сделай это сам:

1. На GitHub открой `docs/app.html` и нажми карандаш (**Edit**).
2. Найди в начале скрипта строки:
   ```js
   var AUTH = {
     supabaseUrl: '',
     supabaseKey: ''
   };
   ```
3. Впиши значения между кавычками:
   ```js
   var AUTH = {
     supabaseUrl: 'https://abcdefgh.supabase.co',
     supabaseKey: 'sb_publishable_...'
   };
   ```
4. **Commit changes**.

## Шаг 8. Проверь

1. Открой опубликованный сайт → **Войти → Создать**.
2. Зарегистрируйся на свою почту. Через несколько секунд придёт письмо «Код подтверждения Nova».
3. Введи 6 цифр. Должна появиться зелёная галочка и кабинет.
4. В Supabase в разделе **Authentication → Users** появится твой аккаунт.

> В предпросмотре внутри Claude настоящий вход не работает: там странице запрещено обращаться к другим серверам. Проверяй на опубликованном сайте.

## Если что-то не так

| Что видишь | Что делать |
|---|---|
| Письмо не пришло | Проверь папку «Спам». Проверь поля SMTP (шаг 5). Ошибки отправки видны в Supabase: **Logs → Auth**. |
| Пришла ссылка вместо кода | Не вставлен шаблон письма (шаг 4). |
| «Код не подошёл или устарел» | Введи код из **последнего** письма: после «Отправить снова» старый код перестаёт работать. Код живёт 15 минут. |
| «Нет связи с сервером» | Нет интернета, или страница открыта в предпросмотре Claude, или проект в Supabase «уснул» (ниже). |
| «Удаление аккаунта ещё не включено на сервере» | Не выполнен `supabase/account.sql` (шаг 6½). |
| «Новое письмо можно отправить через N сек.» | Supabase разрешает одно письмо в минуту на одну почту. Подожди. |
| Проект «уснул» | Бесплатный проект Supabase может засыпать, если им долго не пользовались. Открой панель Supabase и нажми **Restore project**. |

## Важно знать

- **Пароли** хранятся в Supabase в зашифрованном виде. Ни ты, ни Nova их не видят.
- **Почта пользователей — персональные данные.** Страница «Конфиденциальность и условия» — [`docs/privacy.html`](privacy.html), на неё ссылается галочка при регистрации. Если меняешь, где хранятся данные (другой сервис, другая почта-отправитель), поправь и её. Если сайтом будут пользоваться люди из России, учти закон о персональных данных (152-ФЗ). Перед серьёзным ростом проекта стоит спросить юриста.
- **Ключи на шаге 2 публичные**, а пароль базы, `secret`-ключ и пароль приложения Gmail — секретные. Их вписываешь только в панели Supabase или Google, никуда больше.
